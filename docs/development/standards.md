# 开发规范

## 结构与边界

Go 的 `cmd` 负责组装启动，`internal` 存放私有实现，handler 不承载业务规则；服务与存储分离。Vue 页面、组件、API 和状态分层；移动端按 app、feature、core 分层。跨端业务契约统一维护在 `docs/api/`。

## 代码约定

Go 使用 gofmt，错误显式处理并带上下文。Web 使用 TypeScript 和 Vue Composition API，避免 any。Swift 和 Kotlin 遵守各自官方命名习惯。新依赖说明用途，首次安装后提交对应锁文件，升级须验证兼容性。

## API 与安全

未来业务接口使用 `/api/v1`，明确字段、错误和分页语义。外部 RSS 和音频 URL 需要防范 SSRF、限制响应大小和超时。认证授权、日志脱敏、密钥环境变量和数据库迁移应随功能一同实现。健康检查不返回敏感信息。

## 验证

后端：`cd backend && go test ./...`、`go vet ./...`、`gofmt -l .`。Web：`cd web && npm run build`。原生工程生成后补充对应构建命令。新增业务规则和缺陷修复应有适当测试；纯目录和文档变更以结构校验为主。

## 提交与文档

每次提交聚焦一个目的。PR 描述问题、行为变化、验证与限制；架构变更新增 ADR。用户未请求时不自动提交、推送或发布。每次操作收尾遵守根 AGENTS.md 的记忆核对流程。
